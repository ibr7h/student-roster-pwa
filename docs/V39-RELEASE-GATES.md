# v3.9 — خطة ربط معاينة المدارس واختبارات القبول

> **الوضع:** الفرع تجريبي، ولا يجوز توصيله بقاعدة production أو بمجلد ملفات المدارس الحقيقي. لا تتضمن هذه الوثيقة مفاتيح أو معلومات اتصال حساسة.

## عناوين المعاينة
- الواجهة الثابتة: https://school-evidence-v39-preview.onrender.com
- API المستقل: https://school-evidence-v39-api-preview.onrender.com
- فرع Neon التجريبي: `test-v39-unified-auth-20261020` (معرّفه `br-patient-queen-b9il7nzc`)
- حاوية الملفات التجريبية الخاصة: `uploads-v39-preview`، **private**.

## أهم حاجزين قبل تشغيل التسجيل الحقيقي
1. **DATABASE_URL:** خادم المعاينة الحالي يعمل بحالة `database unconfigured`. يُنسخ اتصال فرع Neon التجريبي فقط من لوحة Neon، ثم يوضع يدويًا في Render → خدمة `school-evidence-v39-api-preview` → Environment. لا تستخدم اتصال `production`، ولا تشارك سلسلة الاتصال في المحادثة أو GitHub.
2. **مرسل OTP:** المرسل المتاح ضمن اتصال Resend الحالي تابع لمشروع آخر ولا ينبغي استعماله تلقائيًا. يُعتمد نطاق بريد يخص منصة الشواهد، ويُضاف ويُتحقق منه لدى Resend/DNS. بعد ذلك تضبط قيم `SCHOOL_RESEND_API_KEY` و`SCHOOL_OTP_FROM` و`SCHOOL_OTP_HMAC_SECRET` (سر عشوائي طويل) في Render Environment، وليست في الشيفرة.

## إعداد خدمة المعاينة
1. افتح https://dashboard.render.com ثم خدمة **school-evidence-v39-api-preview**.
2. أضف الأسرار التالية من المصادر الصحيحة:
   - `DATABASE_URL`: اتصال فرع Neon **test-v39** فقط.
   - `SCHOOL_RESEND_API_KEY`: مفتاح API مستقل يمكنه إرسال بريد المشروع المعتمد.
   - `SCHOOL_OTP_FROM`: عنوان مرسل ضمن نطاق الشواهد بعد اعتماده والتحقق من DNS.
   - `SCHOOL_OTP_HMAC_SECRET`: قيمة عشوائية لا تقل عن 32 حرفًا، ثابتة بين عمليات إعادة النشر؛ **لا تطبعها في Logs**.
   - `AWS_ENDPOINT_URL_S3` و`AWS_REGION` و`AWS_ACCESS_KEY_ID` و`AWS_SECRET_ACCESS_KEY`: بيانات خدمة Storage الخاصة بفرع الاختبار مع صلاحيات محدودة.
   - `STORAGE_BUCKET=uploads-v39-preview`
   - `SCHOOL_STATIC_ORIGIN=https://school-evidence-v39-preview.onrender.com`
   - `NODE_ENV=production`
3. بعد حفظ الأسرار، تحقق من تشغيل Render وعبارة اتصال قاعدة البيانات، دون عرض معلومات حساسة في السجلات.
4. اختبر `GET /api/health` و`GET /api/register/status`: الصحة متاحة و`emailReady:true` (هذا يثبت وجود إعدادات الإرسال لا نجاح تسليم رسالة فعلية).
5. اختبر من بريد تجريبي مملوك لك: تسجيل مدرسة افتراضية ورقم جوال اختباري غير مرتبط بشخص حقيقي، استلام 6 أرقام، رفض الخاطئ، التحقق، الدخول، ثم تفعيل مفتاح تجربة مُنشأ في فرع test فقط.
6. اختبر مديرًا وعضو لجنة مختلفين، PDF مضغوطًا، رمز QR، مشاركة محدودة ثم إلغاء الرابط؛ تأكد أن الملفات تُحفظ تحت رقم المدرسة في **`uploads-v39-preview` فقط**.
7. تأكد من عدم ظهور محتويات مدرسة أخرى، ثم نفذ اختبارات iPhone Safari وPWA المثبّت وعودة التطبيق بعد إغلاقه وظهور لوحة المفاتيح.

## اختبارات موجودة
- CI خادم: `.github/workflows/verify-auth-v39.yml`؛ اختبارات المصادقة وPDF والصلاحيات وحدود المحاولات.
- CI تكامل: `.github/workflows/integration-v39.yml`؛ PostgreSQL مؤقت وS3 محلي تجريبي، بدون بريد حقيقي أو أي تعديلات على Neon.
- CI واجهة: `.github/workflows/verify-ui-v39.yml` و`.github/workflows/browser-v39.yml`؛ محاكاة Chromium للجوال 320/390 بكسل مع اعتراض استجابات API.
- نتائج الاختبارات الناجحة لا تحل محل تجربة DNS والبريد وسجل Neon/S3 الحقيقي وأجهزة iPhone.

## بوابات عدم النشر
- ممنوع توجيه `school-evidence-v39-preview` إلى API الإنتاج الحالي.
- ممنوع تطبيق migration على الإنتاج أو استبدال الواجهة المعتمدة قبل اجتياز جميع فحوص البيانات والصلاحيات والبريد والجوال.
- لا تحذف أو تعدّل مفاتيح `SCH-` الحالية ولا تغيّر مدرسة الإنتاج.
- يؤجل ربط البريد بالحسابات القديمة إلى مسار تحقّق خاص، دون مطالبتهم بإعادة تسجيل مدارسهم.
- قبل الإنتاج: نسخ احتياطي، استعادة مُجربة، قبول المستخدم، وخطة رجوع موثقة.
